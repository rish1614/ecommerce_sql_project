# Portfolio Summary

## Project title

**E-commerce Business Analytics — PostgreSQL, SQL, Python & Docker**

## Project objective

Analyze a synthetic e-commerce transaction dataset and convert raw relational data into business insights about revenue, customers, products, returns, and profitability.

## Technology

- PostgreSQL 16
- SQL
- Python
- pandas
- matplotlib
- Docker / Docker Compose
- Jupyter Notebook
- Git / GitHub

## Data scale

- 20,000 customers
- 80,000 orders
- 163,710 order items
- 500 products
- 8 campaigns
- 6,479 return events

## Core SQL skills demonstrated

- Relational joins.
- Aggregation and grouping.
- `CASE` and NULL handling.
- CTEs.
- Date and time analysis.
- `ROW_NUMBER`, `RANK`, `DENSE_RANK`.
- `LAG`.
- Running totals.
- Top-N analysis.
- Retention and churn-style analysis.
- Profitability analysis.
- Reusable SQL views.

## Analyst skills demonstrated

- Defining metrics before calculating them.
- Respecting table grain.
- Data-quality validation.
- Cross-validation between SQL and Python.
- Translating numerical results into business implications.
- Distinguishing descriptive analysis from causal claims.
- Documenting analytical assumptions.

## Business themes identified so far

- Strong Q4 revenue uplift.
- Meaningful reduction from discounts and refunds.
- Need to evaluate retention and customer concentration.
- Need to evaluate product performance using both sales and margin.
- Return behavior is relevant to realized revenue.
- Regional profitability can differ from revenue leadership.

## Why this project is portfolio-worthy

The project demonstrates an end-to-end analyst workflow rather than isolated SQL exercises:

```text
Data generation
      ↓
Database setup
      ↓
Data validation
      ↓
SQL analysis
      ↓
Python analysis
      ↓
Cross-validation
      ↓
Business interpretation
      ↓
Dashboard / reporting
```

## Important limitations

The data is synthetic, and all profitability, segmentation, churn, and campaign interpretations depend on project assumptions. The project should therefore be presented as an analytics engineering / analyst skills demonstration, not as evidence of real company performance.

# Documentation Guide

This folder contains the project documentation for the E-commerce Business Analytics project.

## Documentation map

| File | Purpose |
|---|---|
| `data_dictionary.md` | Tables, columns, grain, relationships, and business meaning of the data model. |
| `data_quality_report.md` | Data-quality checks performed before analysis and the verified results. |
| `methodology_and_metrics.md` | Analytical methodology, metric definitions, SQL conventions, and assumptions. |
| `analysis_guide.md` | How each SQL analysis answers a business question and how to interpret it. |
| `business_findings.md` | Executive findings and recommendations. Update the marked sections after all final analyses are run. |
| `execution_plan.md` | Reproducible setup and end-to-end execution order. |
| `interview_story.md` | A structured explanation of the project for interviews and portfolio discussions. |
| `interview_questions.md` | Technical and business questions you should be able to answer from the project. |
| `dashboard_guide.md` | Recommended dashboard structure, KPIs, visuals, and business narrative. |

## How these documents should be used

The documentation is intentionally separated into four layers:

1. **Data understanding** — what the tables contain and how they relate.
2. **Analytical methodology** — how metrics are defined and calculated.
3. **Business interpretation** — what the analysis means for management.
4. **Interview preparation** — how to explain the work and defend analytical choices.

Keep the documentation synchronized with the SQL and Python implementation. If a metric definition changes, update the methodology document and any downstream findings.
